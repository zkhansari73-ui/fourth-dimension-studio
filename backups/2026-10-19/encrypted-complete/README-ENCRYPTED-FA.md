# آخرین وضعیت بازیابی — ۱۹ اکتبر ۲۰۲۶

این بخش بر گزارش‌های قدیمی‌تر اولویت دارد.

پنج بستهٔ واقعی SQL، core، plugins، themes و uploads در Drive خصوصی و نسخهٔ رمزگذاری‌شدهٔ همهٔ آن‌ها در شاخهٔ backup/site-state-2026-10-19 ذخیره‌اند. ثبت کامل فایل‌ها: 7e02b497547664ec5c1eb8c5a9311778a2f3109f؛ main تغییر نکرد.

آزمون بازیابی ایرادی در SQL اولیه آشکار کرد: ۹۹۱۴ علامت درصد با یک placeholder داخلی وردپرس جایگزین شده بود. اصل حفظ شده است؛ SQL اولیه را مستقیم وارد نکنید. نسخهٔ اصلاح‌شده با SET NAMES utf8mb4 و هش زیر در Drive خصوصی ذخیره شد:
https://drive.google.com/file/d/1CCqpTqoAODjFxXsU-lXoUgLEoOfF5Dgr/view?usp=drivesdk
SHA-256: 0de673e66b1761574075c59e0fa580b7a32400fb38165848f01cc83a363e3092
حجم: 3168756 بایت.

برای نسخهٔ گیت‌هاب: پس از بازسازی و رمزگشایی بسته‌های اصلی، اسکریپت repair-wordpress-sql.py را اجرا کنید:
python repair-wordpress-sql.py decrypted-backup/db-backup-20261019-070845.sql db-backup-20261019-070845-corrected.sql
اسکریپت ابتدا هش اصل، تعداد و یکتایی placeholder را بررسی می‌کند، خروجی را بدون بازنویسی فایل موجود می‌نویسد و هش نسخهٔ اصلاح‌شده را تطبیق می‌دهد. سپس فقط SQL اصلاح‌شده را در پایگاه دادهٔ آزمایشی وارد کنید؛ آن را روی سایت زنده وارد نکنید.

آزمون واقعی آفلاین MariaDB 10.11.7 موفق بود: هر ۱۴ جدول و ۹۳۵ ردیف بازیابی شدند. هش و تعداد بایت متن و هش نشانی پنج نوشتهٔ ۱۵، ۱۶، ۱۹، ۹۲، ۹۴ دقیقاً با وردپرس زنده برابر است. ۶۰۲۱ فایل PHP در چهار آرشیو بدون خطای نحوی هستند. CRC چهار ZIP و هش بسته‌ها نیز سالم است. این آزمون واردکردن واقعی SQL است؛ اجرای کامل وردپرس با HTTP انجام نشده، چون محیط ساخت سوکت سرور را اجازه نمی‌دهد. محدودیت دور زده نشد.

دسترسی عمومی ۱۷ بکاپ موقت روی uploads با بلوک محدود .htaccess بسته شد؛ تک‌تک در مرورگر 403 دادند. تصویر عادی مقاله همچنان باز می‌شود. فایل‌ها هنوز حذف نشده‌اند. ابزار موقت بررسی هش پس از کار غیرفعال و به زباله‌دان منتقل شد. محتوا، نشانی و انتشار نوشته‌ها تغییر نکرد.

پاک‌سازی نهایی: پنج فایل اصلیِ db-backup/core/plugins/themes/uploads به تاریخ 20261019 و دوازده تکهٔ themes/uploads با شمارهٔ part0 تا part5 در uploads هستند. حذف دائمی آن‌ها از مرورگر به تأیید هنگام اقدام نیاز دارد. تا آن زمان دسترسی وب آن‌ها مسدود است. فایل‌های Muse حذف یا لغو اشتراک نشده‌اند؛ دسترسی مدیریتی آن سرویس تأیید نشده است.

پوشش کامل تمام حساب هاست هنوز با فهرست مستقل تطبیق ندارد: mu-plugins و drop-inها، فایل‌های متفرقهٔ wp-content و بیرون از وردپرس، تنظیمات حساب هاست، DNS و ایمیل تضمین نشده‌اند. تنظیمات وردپرس/افزونه‌های ذخیره‌شده در ۱۴ جدول همراه SQL هستند؛ تنظیمات بیرونی سرویس‌ها نیستند. SQL شامل snapshot اسنیپت‌ها نیز هست؛ پیش از راه‌اندازی محیط بازیابی، اسنیپت‌های موقت و اتصال‌های بیرونی بازبینی و غیرفعال شوند. کلید رمزگذاری در Drive جداست و در GitHub نیست.

شواهد: sql-percent-repair.json، sql-live-comparison.json، php-syntax-validation.json. فایل‌های SQL خام و کلید در بستهٔ راهنما قرار ندارند.

# بکاپ رمزگذاری‌شدهٔ کامل بسته‌های دریافت‌شده — ۱۹ اکتبر ۲۰۲۶

تمام پنج فایل اصلی (SQL، core، plugins، themes و uploads) در این پوشه موجودند: هفت بخش رمزگذاری‌شده به ۳۷۶ قطعه تقسیم شده‌اند و همه در parts ذخیره‌اند. هش Git هر قطعه هنگام ثبت با فایل محلی تطبیق داده شد. بازسازی آزمایشی محلی از ۳۷۶ قطعه به هفت بخش و کنترل SHA-256 هر هفت بخش موفق بود.

۱. همین شاخهٔ backup/site-state-2026-10-19 را clone یا دانلود کنید.
۲. داخل این پوشه اجرا کنید: python restore-github-backup.py
۳. کلید خصوصی recovery-key-20261019.txt را از پوشهٔ خصوصی Google Drive خود دریافت کنید؛ کلید در این مخزن وجود ندارد. شناسهٔ فایل کلید در encrypted-manifest.json ثبت است.
۴. Python 3 و بستهٔ cryptography برای رمزگشایی لازم است. اجرا: python decrypt-backup.py --key-file /path/to/recovery-key-20261019.txt --directory reconstructed-encrypted-backup --output decrypted-backup
۵. اسکریپت رمزگشایی پنج فایل اصلی را تولید و هش هرکدام را بررسی می‌کند. رمزگشایی محلی هر پنج فایل قبلاً آزمایش و با هش اصل تطبیق داده شده است.

پیش‌نویس Release فقط سه فایل قدیمی‌تر دارد؛ مرجع کامل همین پوشهٔ شاخه است. هیچ رمز یا کلید خام به GitHub ثبت نشده و main تغییر نکرده است.

دامنهٔ پوشش: بسته‌های تحویل‌شده شامل SQL با ۱۴ جدول، هسته و فایل‌های ریشه، قالب‌ها، افزونه‌ها و uploads است. صحت همهٔ فایل‌های زندهٔ هاست با فهرست مستقل تطبیق نشده؛ mu-plugins، drop-inها، فایل‌های دیگر wp-content، تنظیمات حساب هاست، DNS و ایمیل تأیید نشده‌اند. SQL در موتور پایگاه داده وارد نشده و راه‌اندازی کامل سایت آزمایشی انجام نشده است. پاک‌سازی یا مسدودکردن نسخه‌های موقت هاست و Muse هنوز تأیید نشده است. ذخیره‌سازی و سلامت بسته را با بازیابی کامل سایت اشتباه نگیرید.
