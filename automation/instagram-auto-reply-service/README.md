# پاسخ‌گوی خودکار کامنت اینستاگرام

این سرویس کامنت‌های جدید را می‌گیرد، شناسه پست را با فایل قوانین تطبیق می‌دهد و پاسخ همان پست را از طریق Composio ارسال می‌کند. اتصال فعلی از نوع Managed OAuth است؛ بنابراین حالت پیش‌فرض `poll` است و کامنت‌ها را هر ۶۰ ثانیه از طریق Composio بررسی می‌کند. حالت Webhook مستقیم Meta نیز برای آینده موجود است.

## وضعیت فعلی

- حساب Composio: `pg-test-a758729a-4537-409d-81f5-999891ebd67a`
- اتصال Instagram: `ca_zxlQN-6Mlyz_`
- حساب Instagram: `39109250795339859` (`@fourth.dimension.studio.ai`)
- نسخه ثابت Toolkit: `20260915_00`
- حالت دریافت مناسب اتصال فعلی: `INGEST_MODE=poll`
- حالت پیش‌فرض: `DRY_RUN=true`؛ بنابراین هیچ پاسخی ارسال نمی‌شود.
- فایل قوانین فعلاً خالی است، چون حساب متصل هنوز پستی برنمی‌گرداند.

## تکمیل راه‌اندازی

1. فایل `.env.example` را با نام `.env` کپی کنید.
2. مقدار `COMPOSIO_API_KEY` را فقط داخل `.env` وارد کنید. کلید را در چت نفرستید.
3. پس از انتشار هر پست، شناسه `media_id` و پاسخ‌های همان پست را در `config/replies.json` قرار دهید. نمونه کامل در `config/replies.example.json` است.
4. وابستگی‌ها را نصب و تست‌ها را اجرا کنید:

   ```bash
   npm install
   npm test
   ```

   سپس اتصال را بررسی کنید:

   ```bash
   npm run verify
   ```

5. سرویس را روی یک میزبان Node دائمی اجرا کنید. در حالت `poll` نیازی به Callback یا Meta App Secret نیست.

6. ابتدا در حالت `DRY_RUN=true` یک کامنت آزمایشی بفرستید و وضعیت را از `/health` بررسی کنید.
7. بعد از تأیید نتیجه، `DRY_RUN=false` کنید و سرویس را دوباره اجرا کنید.

## حالت Webhook اختیاری

اگر بعداً یک Meta App اختصاصی و Custom OAuth در Composio ساخته شد، `INGEST_MODE=webhook` را انتخاب کنید و مسیر عمومی زیر را در Meta Webhooks ثبت کنید:

   ```text
   https://YOUR_HOST/webhook
   ```

در این حالت `META_APP_SECRET` و `META_VERIFY_TOKEN` نیز لازم‌اند و فیلد `comments` باید در Meta فعال باشد.

## رفتار ایمن

- امضای `X-Hub-Signature-256` Meta بررسی می‌شود.
- رویداد تکراری دوباره پاسخ داده نمی‌شود.
- کامنت مخفی، کامنت خود حساب و پاسخ‌های زیرکامنتی به‌طور پیش‌فرض نادیده گرفته می‌شوند.
- فقط پست‌هایی که صریحاً در `config/replies.json` فعال شده‌اند پاسخ می‌گیرند.
- خطای پیش از شروع ارسال با تأخیر دوباره امتحان می‌شود و بعد از سقف تعیین‌شده به dead-letter می‌رود.
- متن پاسخ پیش از ارسال از نظر سقف ۳۰۰ کاراکتر، تعداد URL و هشتگ اعتبارسنجی می‌شود.

### جلوگیری از پاسخ تکراری

پیش از ارسال پاسخ واقعی، وضعیت `sending` روی دیسک ثبت می‌شود. اگر سرویس هنگام ارسال قطع شود یا نتیجه درخواست شبکه نامعلوم باشد، آن رویداد با وضعیت `delivery_unknown` به dead-letter منتقل می‌شود و خودکار دوباره ارسال نخواهد شد. این انتخاب از پاسخ عمومیِ تکراری جلوگیری می‌کند، اما چون Instagram/Composio برای این عملیات کلید idempotency در اختیار سرویس نمی‌گذارد، تضمین دقیق «فقط یک بار» ممکن نیست و ممکن است در این وضعیت مبهم یک پاسخ ارسال‌نشده باقی بماند. چنین موردی باید دستی بررسی شود.

خطاهایی که پیش از شروع ارسال رخ دهند همچنان با تأخیر دوباره امتحان می‌شوند. هنگام توقف عادی نیز سرویس منتظر عملیات فعال می‌ماند و سپس خارج می‌شود.

## نکته استقرار

این نسخه برای یک فرایند Node دائمی با دیسک پایدار طراحی شده است. برای اجرای چندنمونه‌ای یا Serverless، فایل `JsonStateStore` را با Redis یا یک پایگاه‌داده تراکنشی جایگزین کنید.

فایل dead-letter می‌تواند متن کامنت و نام کاربری را نگه دارد؛ برای استقرار طولانی‌مدت، نگهداری و پاک‌سازی دوره‌ای آن را مطابق سیاست حریم خصوصی خود تنظیم کنید.
